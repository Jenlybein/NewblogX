# ADR-0030：发布质量闸门改为异步判定——提交立即返回，评分未达标退回草稿并通知

- 状态：已交付
- 日期：2026-11-13
- 来源：[#386](https://github.com/Jenlybein/NewblogX/pull/386) 之后的产品口径（用户反馈：更新文章提示"请求超时"）

## 背景与问题

发布质量闸门（ADR-0023）在**提交请求里同步评分**：`POST /articles`、`PUT /articles/{id}`
的顺序是「配额预占 → 同步风险扫描 → 模型评分（5–30 秒）→ 判定 → 落库」。而读者站/后台的
HTTP 客户端默认超时是 15 秒（`services/http/client.ts` 的 `DEFAULT_TIMEOUT_MS`）。

线上实测（2026-11-13，`gentlybeing.cn`）：

```
PUT /api/articles/378600185447583744  200  14.1s
PUT /api/articles/378600185447583744  200  15.0s
```

客户端在 15 秒掐断、弹「请求超时」，服务端却在 15.0 秒返回 200——**文章其实已经更新了，
界面却告诉作者失败**。作者既无法判断该不该重试（重试会再烧一次模型调用），也拿不到评分结果。
同时作者被迫在写稿页等 15–30 秒，心态上是"页面卡住了"。

审核（合规判定）本来就已是异步的（ADR-0024：发件箱 `complianceSubscriber` 判定后才放开
可见）。阻塞的只有质量闸门这一处同步模型调用。

## 决策

1. **提交请求里不再评分**。顺序改为「配额预占 → 同步风险扫描（纯字符串匹配 + 一次评分记录读）
   → 落库 → 立即返回」，请求耗时回到几十毫秒。HTTP 层把闸门策略的 `Deferred` 置 `true`。
   闸门开关、及格线、灰带、木桶口径**全部不变**（仍是 ADR-0023 的规则），只换执行时机。
2. **异步链路顺序固定为「评分 → 质量判定 → 合规判定」**，靠发件箱订阅者的注册顺序保证
   （`runSubscribers` 串行执行）：
   - `scoreSubscriber`（已有）：确保文章有评分记录；
   - `qualityGateSubscriber`（新增）：读已有评分做判定，未达标**退回草稿**并通知作者；
   - `complianceSubscriber`（已有）：合规判定通过才把 `pending_review` 放开为可见。
   质量判定排在合规之前，保证**没过质量线的文章永远不会先被合规放行、再撤回**。
3. **未达标的落点是草稿**（`Article.DemoteForQuality`）：作者改完可立刻重投，与同步时代
   的落点一致；同时发一条站内通知，带「分数 / 放行线」，告诉作者改哪儿、差多少。
4. **失败关闭**：异步链路拿不到可用分数（端口缺失、模型失败）时返回错误，由发件箱重试；
   重试耗尽进死信。文章停留在 `Published + pending_review`（**对读者不可见**），
   不会因为"评不了"就被当作干净放行。
5. **事件可重复投递**：退回草稿只在「已发布待可见」这一档生效，其它状态直接跳过；
   通知按「接收者 + 链接 + 内容」去重，重放不会出现两条一样的通知。
6. **前端不再有「评分中」等待态**：提交成功即提示「已提交，后台评分与审核中，通过后对读者可见」
   并立刻跳转离开编辑页；按钮文案从「评分中…」改为「提交中…」。

## 理由与已否决方案

- **否决「把 HTTP 客户端超时调到 60 秒」**：只治报错，不治"作者被钉在页面上等模型"；而且
  "超时但已成功"的模糊状态依然存在。
- **否决「前端先乐观跳走、后端仍同步评分」**：质量不达标时文章会被落成草稿，作者却已经离开
  编辑页、看不到分数与建议；表现成"我明明发布了，文章却没公开也没提示"。
- **否决「关掉质量闸门」**：低质内容会直接公开，闸门的产品目的（先评再发）就没了。
- **否决「提交返回 202 + 前端轮询评分结果」**：要新增任务状态端点、前端轮询与超时兜底，
  复杂度远高于"落库存事件 + 发件箱判定 + 通知"；并发/重试语义还要重新定义。
- **否决「把闸门判定塞进合规订阅者里」**：会让合规订阅者承担两种职责，且两者失败语义不同
  （质量不达标要退回草稿、合规存疑要转人工）；独立订阅者让"谁在什么时候动文章状态"一眼可读。

## 当前生效约束

- 提交路径里**不得**再出现模型调用；`QualityGatePolicy.Deferred` 为 `true` 时同步分支必须跳过。
  （`Deferred=false` 只保留给用例验证 ADR-0023 的判定规则本身，生产 HTTP 层永不为 false。）
- 质量判定只读**已有评分记录**（`ModerationScorePort.LatestScores`），不得在异步链路里再调模型。
- 质量未达标的文章只能落在草稿；合规判定不得把未过质量线的文章改成可见。
- 异步链路拿不到分数必须失败关闭：文章保持不可见、事件重试、耗尽进死信，不得静默放行。
- 通知文案必须带分数与放行线，且去重口径与其它系统通知一致（同接收者 + 同链接 + 同内容）。
