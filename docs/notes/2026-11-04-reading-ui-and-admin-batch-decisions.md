# 阅读页互动真相、版式、评论面板与后台 UI：决定清单（2026-11-04）

本轮输入来自读者反馈与后台截图，共 **8 组**改动。每条都是经对话确认的口径，**未确认的地方不写在这里**。

## 0. 现象与根因（已核实的事实）

1. **点赞后刷新，按钮已赞但计数不更新**。写路径本身是对的（写响应回填权威计数、无本地 ±1）。错的是**刷新后计数的来源**：硬刷新命中的是**按 URL 键的 30s 匿名 SSR HTML/payload**，里面烤着写之前的 `digg_count`；hydration 又把它灌进客户端 30s SWR（再续 30 秒）。登录私有态请求 `article-private-<id>` 明明又打了一次**带鉴权的详情**（同一份响应里就有权威计数），却按 ADR-0024 约束 2 只投影 `is_digg` / `is_favor`，把计数丢掉 → 「新状态 + 旧数字」。收藏数同一病理。
2. **后端计数是双账本**：关系表（状态真相）+「库内列（30 分钟 cron 落库）+ Redis 增量」（计数真相）。增量是 ±1，丢一次就**永久偏**，没有任何重算路径把它拉回来。
3. **`GET /articles/favorite/contents` 读路径缺一步**：SQL 直接 join `article_models` 读列，不并 Redis 增量，所以同一篇文章会出现「详情页 6、收藏列表 5」。
4. **阅读页底部多出一条互动条**：`article/[id].vue` 挂载了两个 `ArticleActionsBar`（右栏 `--aside` 与 `<1024px` 的 `variant="fixed"`）。CSS 本应互斥（`--fixed` 在 ≥1024 是 `display:none`），但读者在 1280px 下同时看到两份；本机无法复现（无前端实例、docker 不可达、`http://localhost` 不通），**病因未证**，处理方式见 §3。
5. **后台用户管理**：头像兜底取 `(nickname || username).slice(0,1)`，对邮箱用户名会画出无意义的 `1`；表格 7 列 minWidth 合计 1020px 被塞进 15/24 格且无 `scroll-x`，右侧两列被裁；封禁能力后端早有（`user/domain/rule.go`：仅管理员可改、不能改自己；改状态会吊销全部会话），但只有右侧表单一个入口。
6. **后台设置表单拉满**：`Settings*.vue` 全是手写 `NForm + NFormItem + NInput`，`NFormItem` 内容区默认 `width: 100%`，后台 CSS 里没有任何 `n-form` 宽度规则。
7. **合集/项目页**：现在是「顶部新建/编辑表单卡 + 表格」，编辑/删除常显；目录树编辑在**独立页** `pages/articles/outline.vue`，整树一次性提交，且 **ADR-0023 明确否决了拖拽排序**。

## 1. 计数真相（前端）

1. 私有态源 `article-private-<id>` 的投影从 2 字段扩到 **4 字段**：`is_digg / is_favor / digg_count / favor_count`（响应仍是那把带鉴权的详情，只投影这 4 项）。
2. 回填时 4 项一起 patch 回正文；`articleDiggTouched` 为真时不覆盖（**保护范围要覆盖计数**，不只是布尔——否则晚到的私有态响应会把写响应回填的计数打回旧值）。
3. 计数**仍不进 payload / SWR**（`ssr-anonymity.test.ts` 的「所有人共享的数字」口径不变），私有态源也永不进缓存。
4. 匿名读者仍 ≤30 秒滞后（ADR-0024 决策 5 不动）。
5. 新增门禁：**行为层**断言「刷新路径必须用私有态响应回填计数并覆盖 payload 旧值」；**源码层**锁 4 字段投影。

## 2. 计数账本与并账（后端，ADR-0025）

6. 并账（30 分钟 flush）从 `列 += 增量` 改成 `列 = COUNT(关系行)`；**`digg_count` 与 `favor_count` 都覆盖**。
7. 读路径仍是 `列 + 增量`，**用户看到的数字永不等 30 分钟**；30 分钟只是并账周期，并账前后 `列+增量` 守恒。
8. 诚实记录瑕疵：并账瞬间存在**临时 ±1**（同一次事件可能被 COUNT 与增量各算一次），不累积，下一轮覆盖即自愈。
9. 理想形态（CDC：binlog → 计数投影）**列为显式非目标**，不开票。
10. `GET /articles/favorite/contents` 的读路径**补上增量合并**（与详情/列表同一口径），本批顺手修。
11. 既有读口径不变：`enrichCounters` 仍是唯一把增量叠进计数的地方。

## 3. 阅读页互动条与版式

12. 删掉 `variant="fixed"` 的第二处挂载点与全部 `--fixed` CSS（含 `position: fixed` 那段与 `.article-page` 的 `padding-bottom`）。
13. `ArticleActionsBar` 两形态：`aside`（≥1024 显示）与 `hero`（<1024 显示，位于 hero 下方、正文开头）；任何宽度只出现一份，**底部永远没有**。
14. 顺序固定为 **点赞 收藏 评论 分享 底部**；5 等分、每格约 56px；前四个带数字，**「底部」图标-only**（`IconArrowDownToLine`，语义在 `aria-label` / `title`）。
15. 「评论」= 直接开输入面板（不滚动、不聚焦）；「底部」= 滚到**评论区起点（正文末尾）**，照旧尊重 `prefers-reduced-motion`。
16. 删掉「评论第 X 页，每页 7 条。」这行文字；`上一页 / 下一页` 保留；**第一页且没有下一页时整行（含按钮）都不渲染**。
17. 门禁 `articleActionsLayout.test.ts`：从「必须两个实例」改成「**恰好一个可见**」（两个挂载点 + 互斥档位成对断言），并删掉 `ArticleActionsBar.test.ts` 里 `variant: "fixed"` 的用例。

## 4. 评论输入面板

18. 评论区里的内嵌 `CommentComposer` 退役，换成**「去发表评论」按钮**：放在原输入框位置、复用 `article-action--primary`（墨实底白字）+ `IconMessageCirclePlus`；未登录点击 → 先弹登录框、不打接口、不展开面板。
19. 新增底部滑出面板：宽 `min(92vw, 640px)` 居中、贴窗口底、上方圆角 `--radius-xl`、纸面实体底、**不加暗色遮罩**（透明点击捕获层）。
20. 关闭：点面板外 + `Esc` + 右上 ×；动效 320ms 上滑（`prefers-reduced-motion` 直接出现）；**面板内只保留提交按钮**（没有取消/清空），回复目标靠关闭清掉。
21. 头部：把手小横条 + 标题行（「发表评论」/「回复 X」）。
22. 不锁 body 滚动；最大约 `60dvh`，移动端按 `dvh`。
23. 楼层「回复」→ 直接开面板（标题「回复 X」）并聚焦；提交成功 → 收起面板、清回复目标、刷新该楼层与正文。
24. 评论列表（内容）位置不动。`useArticleCommentJump` 退役，登录前置并入新的开面板入口；未登录时**不再显示任何提示文案**（靠点击弹登录框）。
25. `CommentComposer` 的假标签行（接口设计 / 数据流 / 分页 / 鉴权）退役。

## 5. 顶栏

26. 顶栏文案「消息中心」→「消息」，含 `<640` 折叠面板的 eyebrow 与两处 `aria-label`；`/messages` 页面标题仍是「消息中心」，GLOSSARY 术语不动。
27. 「历史」套 `.site-action` 胶囊（边框 + 图标 + 文字），出现档位从 **≥1280 提到 ≥1024**（与消息同档）；需验 1024–1279 动作区不溢出。

## 6. 后台用户管理

28. 抽一个后台 Avatar 组件：有 `src` 显示；无头像时兜底优先**昵称首字母**，昵称是邮箱形式时画**人形图标**（不再出现 `1` / `a` 这类无意义字符）；并复用读者站 `resolveAvatarUrl` 处理相对路径。
29. 用户表格**占满内容区**（不再 15/24 格）+ `scroll-x` 兜底；编辑从右栏表单改成**抽屉**。
30. 行内「封禁 / 解封」按钮 + 二次确认：封禁 = `status 3`，解封 = `status 1`；**自己那一行禁用**（后端也会拦，前端不该先给入口）。

## 7. 后台设置表单宽度（同上「不许铺满」原则）

31. 按**语义逐字段设宽**，不做一刀切：URL 类 ≤ 560px、密钥类 ≤ 480px、bucket / 前缀类 ≤ 280px、数字类 ≤ 180px、下拉 ≤ 320px；只作用于「站点配置」各面板，不碰文章编辑器与富文本。
32. 宽度用后台自己的 class 表达（如 `.admin-field--url`），不写裸像素到组件里；两列并排只用于数字/开关这类短字段。

## 8. 合集 / 项目管理页重构

33. 列表改成**封面卡片网格**（≥3 列自适应）：封面 + 标题 + 描述 + 篇数 + 展示开关；**hover 才浮出「编辑 / 删除」**。合集与项目同一套版式（两个页面共用卡片组件）。
34. 上方加「新建合集 / 新建项目」按钮 → **弹窗**（只填基本信息：标题、描述、封面、展示），**不含目录编排**。
35. 编辑也是弹窗：信息卡居中；卡内「**编排目录树**」按钮 → **抽屉从信息卡右侧滑出**，两容器**成组居中**（信息卡为 `min(92vw, 560px)`、抽屉 `min(88vw, 480px)`，窄屏改为上下堆叠）；抽屉内**独立保存按钮**。
36. 目录树编辑器（含批量搜索收录、新建文件夹、失效清理、上移/下移/缩进/移出）**抽成共享组件**，弹窗与任何其它入口共用；**删掉独立的「目录编排」页**及其菜单项（编排只在合集/项目弹窗里）。
37. 拖拽用 **sortablejs**（不加自制 HTML5 DnD）：单列表 Sortable + 落点换算成 `(parent, index)`，再落到本地扁平行；按钮式仍保留作为键盘/无障碍入口。
38. **仍是整树一次性提交**：拖拽只改本地行，点「保存」才落库；不新建单步接口（ADR-0023 约束 7 继续生效）。
39. ADR-0023 追加「后续修订」记录拖拽翻案：否决理由针对的是 HTML5 DnD 的脆性；改用成熟的 sortablejs，并保留按钮式路径与整树提交。
40. 卡片网格与两个弹窗都**不得 100% 铺满**。

## 9. 全局约束（本批新增）

41. **禁止 100% 全屏宽容器**：设置表单、弹窗、抽屉、卡片都不许 `w-full` 铺满；宽度由语义 class 决定。
42. 色彩仍只走语义 token（ADR-0012），不新增色相；所有新控件复用 `--radius-*`、`--motion-*`。
43. **正文列宽（阅读页）**：行宽 token 从 `68ch` 提到 `80ch`（约 40 个汉字/行，仍在中文可读区间）；同时 ≥1280 时正文列整体收在 `72rem` 内并居中——多出来的宽度变成纸面外的页面底色，而不是纸面里的空白。窄屏行为不变。改动只落在 `--type-measure` 一个 token 与 `.article-main` 一条断点规则，**不改**卡片与网格结构。


## 10. 票务

一张 spec（本文件为正文）+ **7 张子票**：

1. 计数真相（前端私有态 4 字段 + 门禁）
2. 计数账本（COUNT 并账 + favorite/contents 增量读 + ADR-0025）
3. 阅读页互动条与版式（删固定条、五按钮、窄屏 hero、删分页提示）
4. 评论输入面板（去发表评论按钮 + 底部滑出 + 回复流）
5. 顶栏（「消息」文案 + 历史胶囊）
6. 后台用户管理（头像 / 表格 / 抽屉 / 封禁解封）
7. 后台设置表单宽度 + 合集/项目管理页重构（卡片网格 + 弹窗 + 抽屉编排 + 拖拽）

## 11. 已知取舍与风险

- 匿名读者的计数滞后 ≤30 秒（ADR-0024 决策 5）不变。
- 并账瞬间的临时 ±1（不累积）。
- 后台 UI 改动较多，需要在 1024 / 1280 两档实测：顶栏动作区不溢出、弹窗+抽屉成组居中在窄屏会堆叠。
- 底部重复条的**病因未证**：本批按 §3 删除第二处挂载点；若重建后仍出现，需要那条元素的 DevTools class 才能继续定位。
