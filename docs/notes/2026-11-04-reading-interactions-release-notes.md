# 2026-11-04 阅读互动与消息中心批次发布说明与冒烟清单

- 批次：spec [#234](https://github.com/Jenlybein/NewblogX/issues/234)，子票 #235–#245 已全部合入集成分支 `feat/234-reading-interactions`；收尾补齐 #247（WS 重连、陌生人拒绝文案分级、分享免登录）
- 范围：点赞/收藏真相（SWR 收窄 + 私有态独立取数 + 幂等目标态 + 写响应回填）、阅读页右栏互动条与窄屏底部条、右栏高度响应式、评论区（子评论点赞 / 回复目标 / 焦点 / 图标与胶囊 / 统一登录前置）、消息中心顶级页 `/messages` 与私信并入、历史记录顶级页 `/history` 与后端 keyword/游标/清空/90 天清理、裁剪弹窗尺寸、陌生人私信用户级开关、正文 markdown 色板与六层标题装置
- 契约：本批有**破坏性变更**（点赞请求体、历史分页），三端必须同批上线；后端 `backend/docs/swagger.json` 与两端 `app/types/openapi.d.ts` 已随代码重新生成
- 数据库：**无新表、无列变更、无 DDL**，部署时不需要跑 `-db`；历史清理只改行（软删 `deleted_at`）

## 破坏性变更（先读这一节）

| # | 接口 / 行为 | 旧口径 | 新口径 | 旧调用会怎样 |
| --- | --- | --- | --- | --- |
| 1 | `PUT /api/articles/{id}/digg` | 无请求体，语义是 **toggle** | 请求体**必填** `{"liked": <目标态>}`（`true` = 点赞，`false` = 取消），语义是**目标态**（重复同态即无操作）；响应 `{"is_digg", "digg_count"}` | 空请求体或 `{}`（缺 `liked`）都会失败：HTTP 200 + 业务码 **1002**（空 body 提示「请求体不能为空，请在 Body 中传 JSON 参数」，缺字段提示 `liked` 必填）——本项目失败统一走包体业务码，不是 HTTP 4xx。**不会再被当成 toggle**，因此陈旧按钮不会再取消真实点赞 |
| 2 | `GET /api/articles/history` | `page` + `limit`（offset 分页） | 去掉 `page`；新增 `keyword`（标题模糊搜索）、游标 `before_updated_at` + `before_id`（**必须成对**，只传一个报参数错误）、`limit`（缺省 10、上限 100）；响应 `{list, has_more}` | 继续传 `page` **不报错但不再生效**：每次仍返回第一页，"加载更多"会原地打转。必须改成游标续页 |
| 3 | `DELETE /api/articles/history/all` | 不存在 | **新增**：清空当前登录用户的全部浏览历史，无请求体、不可逆（软删）；前端必须二次确认 | 纯新增，不影响旧调用 |
| 4 | `PUT /api/users/info` | 无陌生人开关字段 | 新增**可选** `stranger_msg_enabled`（`*bool`：不传不改，`false` 是合法值）；`PUT` 自身的响应仍是空 `data`（`{}`），新字段的回显在 `GET /api/users/detail` 的响应里 | 纯增量：旧客户端不传即保持原值 |
| 5 | 错误码 | 陌生人被拒只有 `chat.stranger_disabled` | 新增 `chat.recipient_stranger_disabled`：接收方个人开关关闭（站点级仍是 `chat.stranger_disabled`） | 纯增量；前端按码分支时要分开处理——站点级让人找管理员，接收方级让人找对方（找管理员查不出问题） |

附带的**响应增量**（非破坏性，但本批前端依赖它）：

- 收藏添加 / 移除（`POST /api/articles/favorite`、`DELETE /api/articles/favorite/contents`）的 `data` 由 `{}` 改为 `{is_favor, favor_count}`，计数是权威值。
- 点赞响应新增 `digg_count`；`is_digg` 仍返回。

行为层面的放宽（**非破坏性**，但要写进发布沟通）：

- **分享不再要求登录**：分享是纯前端剪贴板、不打任何接口，游客也能复制文章链接。互动统一登录前置只覆盖点赞 / 收藏 / 关注 / 评论提交。
- 阅读页版式：hero 只留「质量评分 + 编辑」，点赞 / 收藏 / 分享 / 评论移到右栏（<1024px 降级为底部固定条）。
- 路由：消息中心提升为顶级页 `/messages`，历史提升为顶级页 `/history`（见下一节）。

## 数据策略变更：浏览历史保留 90 天

- 保留期 90 天（`backend/internal/article/domain/viewhistory` 的 `Retention`），由**每日 04:10** 的清理任务执行（注册在 `backend/app/cron_wiring.go`，只在 `-role` 含 `cron` 的进程上跑）。
- 清理是**软删**（写 `deleted_at`），与用户手动"移出历史"同一语义，误清可回滚；不会物理删除行。
- 保留期**不是后台配置项**：没有开关、没有运行时参数；改它要改代码并同步改本发布说明。
- 上线后第一次清理在次日凌晨执行，**不会**在部署当时删数据。

## 路由与入口变更

| 路由 | 说明 | 旧路径 |
| --- | --- | --- |
| `/messages` + `/messages/{comments,digg,system,global,chat}` | 消息中心五个子项；`ssr: false` + `auth`；入口 `/messages` 落到默认子项 | `/studio/inbox` → **客户端中间件**按 `tab` / `group` 语义重定向（不是服务端 301） |
| `/history` | 浏览历史独立页；`ssr: false` + `auth` | `/studio/history` → **服务端 301** 到 `/history`（客户端中间件兜底） |

顶栏两个新入口（登录后出现）：消息中心是悬浮面板（展开五子项并显示未读数；`≥1024px` 图标 + 文字、`640–1023px` 图标 + 红点、`<640px` 收进折叠面板）；历史是普通链接（`≥1280px` 常显、`640–1279px` 收进头像菜单、`<640px` 收进折叠面板）。个人中心不再有消息与历史入口。

## 部署要点

1. 备份数据库（本批不改表，但契约与行为变更回滚时仍需要数据基线）。
2. 停服后**串行**重建三个镜像（内存受限机器不要并行构建）：`blogx_server` / `blogx_web` / `blogx_admin`。
3. **不需要**跑 `-db`，也**不需要**重建 ES：没有新表、没有索引映射变更。
4. `docker compose up -d --force-recreate blogx_web blogx_admin blogx_server`，然后 `docker compose restart nginx`（否则 502）。
5. 健康检查（`/health` 200、`/health/ready` 无 `failed` 组件）→ 下面的冒烟清单。
6. 三端**同批**上线：契约在点赞与历史两处是破坏性的，只升一端会出现"按钮点了没反应 / 历史加载更多重复第一页"。

完整部署序列见 [README §11.4.5](../../README.md#1145-本批234-合批阅读互动消息中心与历史记录的一次性部署序列)。

## 已知限制

1. **别人看到的点赞 / 收藏计数可能滞后 ≤30 秒**：共享 SSR HTML 缓存不跨进程 purge（ADR-0024 决策 5 的明确取舍）；写操作本人立即正确。
2. **登录用户仍是「先渲染匿名态、客户端补齐后跳变」**：点赞态不进 SSR payload（ADR-0019 约束 2），ADR-0024 没有改变这个观感。
3. **`/studio/inbox` 的重定向是客户端中间件**，没有服务端 301：爬虫 / 无 JS 客户端访问旧地址只会拿到 SPA 空壳。`/studio/history` 有服务端 301。
4. **历史 90 天是数据策略、不是配置**：后台没有开关，改保留期要改代码 + 改本发布说明。
5. **重连只校准未读总数**：断线窗口内没到达的通知不会逐条补发，只在下一次拉列表时出现；重连成功后的那次汇总只保证"数字对"，不保证"提示一条不丢"。
6. **本文档未在真实环境代跑**：以上冒烟项需要部署后用真实账号 + 浏览器执行；本机只重跑了 `frontend` 门禁（`vitest run` / `typecheck`）与后端 `go build ./...`，集成用例（`-tags integration`，需容器）没有重跑，线上验收仍按上表执行。
