# 架构决策记录（ADR）

本目录是 v2 阶段的决策入口，**一条决策一个文件**：0001–0009 是 v1 后端架构决策，0010–0021 是 v2 阶段的呈现层、前端行为、装饰层与站点策略决策（0020 曾是零 DDL 例外授权与通用取景表立项，0021 是正文内联 SVG），0022 是私信双通道，0023 是合集/项目的目录树，0024 是阅读页用户态与计数真相，0025 是计数账本、配置化并账与单一权威读路径（计数降为派生值），0026 是私信发送资格（一次判完、一律失败关闭，含 `chat_block_models` 立项），0027 是消息中心的排序、复合游标分页与整会话已读（修订 ADR-0022 的清除水位口径），0028 是合集目录树 / 项目目录树成为唯一对外形状（取代 ADR-0023），0029 是配置段注册表与九段具名化（与 0028 各自独立、互不取代）。需要改某条规则或某个取舍前，先读这里对应的 ADR；后端架构的硬约束总表是 `docs/architecture/overview.md` §六，ADR 记录的是每条约束的**出处与理由**；前端呈现层的约束写在各自 ADR 的「当前生效约束」里。

## 新增 ADR 的规则

1. **编号**：四位补零、严格递增，不复用、不跳号、不为插入而重排既有编号。
2. **命名**：`NNNN-短横线小写英文.md`，名字写"决策"而不是"问题"（例：`0007-id-string-type-as-truth.md`，而不是 `0007-id-type-bug.md`）。
3. **状态取值**只有五个：`提议` / `已接受` / `已交付` / `已取代`（superseded，[`docs/README.md`](../README.md) 里的写法）/ `已否决`。一份 ADR 同时只有一个状态；`已取代` 必须在正文写明被哪条取代（如"已取代（by ADR-0012）"）。已交付的 ADR **不改结论**——只能追加"后续修订"小节，或另开一条新 ADR 并在旧条目状态里标 `已取代`。
4. **正文结构**固定，顺序不变：
   1. `# ADR-NNNN：<标题>`
   2. `- 状态：` / `- 日期：` / `- 来源：`
   3. `## 背景与问题`
   4. `## 决策`
   5. `## 理由与已否决方案`
   6. `## 代价 / 不做什么`
   7. `## 当前生效约束`（不得为空）
   8. `## 相关代码与文档`（链接到对应的 `../architecture/` 文档与具体代码路径）
5. **登记**：新增后在本文索引表补一行，并在"关联文档"列写清它落在 `docs/architecture/` 的哪一篇。呈现层等没有 `architecture/` 专篇的决策，链接到 spec 笔记与根 `GLOSSARY.md`，**不要**为它另造一篇 architecture 文档——概念只在 GLOSSARY 定义一次，避免两处漂移。
