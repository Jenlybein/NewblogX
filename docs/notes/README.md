# Notes

按日期记录的过程性文档：复盘、上线记录、排查经过。它们回答「当时发生了什么、为什么这么做」，**不承担现行规则职责**——规则以 `docs/architecture/` 与 `docs/adr/` 为准。

## 命名

- `YYYY-MM-DD-<slug>.md`，例如 [`2026-10-29-regression-review.md`](./2026-10-29-regression-review.md)。
- 一轮改动 / 一次故障 / 一次上线 = 一篇；不按"版本号"组织（旧的 v1/v2 目录已取消）。

## `memory/`

`memory/` 是 agent 长期记忆，2026-10-29 从原 `.workbuddy/memory/` 迁移而来：

- [`memory/MEMORY.md`](./memory/MEMORY.md)：**固定事实与约定**（环境、线上拓扑、不可违背的约定）。随现状更新，读文档前优先看它。
- `memory/YYYY-MM-DD.md`：历史日志，按原样保留，不回头改写（路径与命令可能已过时）。

## 什么时候写

- 修完一个"看起来成功、实际没生效"的问题 → 写复盘，留下失效形状与排查手法。
- 做完一次上线 / 迁移 / 回滚 → 写记录，留下数字与坑。
- 只在脑子里想过的取舍 → 若变成决策，写 ADR；若只是过程，写这里。
