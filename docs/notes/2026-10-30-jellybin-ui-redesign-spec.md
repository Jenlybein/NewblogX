# JellyBin / 果冻盒：双前端视觉体系重构与「捏捏」AI 入口

> 状态：spec，待发布到 issue tracker（`Jenlybein/NewblogX`）并打 `ready-for-agent`。
> 来源：2026-10-30 一轮 20 个决策的 grilling 会话 + 三个只读探查 Agent 的事实报告。
> 适用边界：只碰 `frontend/` 与 `frontend_admin/` 的呈现层，后端与契约不动。

## Problem Statement

读者站和后台现在都长成了"模板感的 SaaS 界面"，不是用户想要的博客样子。

- **配色是通用货**：主色是一套发灰的青绿（`#0f766e`），中性色是 Tailwind 石板灰，页面底色是奶油到冰蓝的三段渐变。用户要的是克莱因蓝 + 奶油白 + 包豪斯黄 + 珊瑚橙 + 暖灰这一套有明确立场的配色。
- **品牌还是旧的**：站名 "BlogX"，页头是一个写着 `BX` 的文字方块，全站没有一张 logo 资产，没有中文站名。用户要把站点改名为 **JellyBin（果冻盒）**，并用自己做的果冻盒 logo。
- **AI 入口生硬且割裂**：AI 只有一个入口——首页右栏 AI 卡片里一个"进行对话"按钮，点开是居中 980px 的白色模态框，气泡永远带着 1px 边框、没有任何过渡、没有打字效果、没有空状态引导；它还把 `#ffffff !important` 写死在卡片上，切暗色时像一块补丁。用户要一个**右下角常驻的"捏捏"**（果冻方块角色），把生硬的对话框换成从它身上长出来的面板。
- **暗色模式是半成品**：站内有 cookie 驱动的开关和 Naive 主题切换，但因为两个前端都没有 Tailwind 配置，Tailwind 走默认 `darkMode: "media"`，那 8 处 `dark:` 工具类**只跟操作系统、不跟站内开关**；AI 卡片/面板被硬编码白色钉死；原生控件 `color-scheme` 也固定为 light。
- **中文一直在用系统字体**：`@fontsource/noto-sans-sc` 装在依赖里，但从未被 `@font-face` 加载，中文实际掉到 PinFang/MS YaHei。
- **没有动效体系**：没有 motion 库、没有 `<Transition>`、没有滚动入场、`prefers-reduced-motion` 全仓 0 处；`motion-v` 明确要求被引入。
- **后台更荒**：后台连 `app.head` 都没有——没有 title、没有 lang、没有 favicon 链接（`public/favicon.ico` 是孤儿文件），品牌仍是 4 处 "BlogX" 文本。

结果是：站点能用，但用户认为它不"高级"，也不像一个人做的博客。

## Solution

对两个前端做一次**呈现层重构**，不碰后端、契约、路由与部署标识：

1. **一套五色语义 token**：克莱因蓝 `#002FA7` / 奶油白 `#FDFBF6` / 包豪斯黄 `#F5C518` / 珊瑚橙 `#FF6B4A` / 暖灰 `#F2EEE6`，锁死五个色相，只为小号文字与 1px 结构线派生同色相的明度变体（黄永不作为字色）。
2. **图纸工程感构图 + 包豪斯几何点缀**：1px 克莱因蓝结构线分栏、40px 暖灰网格底纹、三角/方/圆的形状语义、圆角收归 0、页脚整块克莱因蓝铺色，但保留博客的长文阅读感。
3. **品牌落地**：改名 JellyBin / 果冻盒，双套 logo（高清 3D 原图 + 重绘的扁平矢量果冻 glyph）、完整 favicon/OG/字标、`app.head` 补齐。
4. **"捏捏"（Jelly）**：读者站右下角常驻的果冻方块软体角色，只在非创作页出现；可拖拽并记忆位置；闲置呼吸、悬停挤压、AI 关闭时"睡着"。
5. **AI 面板从捏捏身上生长**：打开时捏捏被压成面板右下角把手，关闭回弹；非遮罩软面板，保留 SSE 流式、6 轮历史、中断重发，新增打字光标与快捷问句空状态。
6. **暗色模式重新派生**：暗色 = 克莱因蓝铺底 + 奶油白字 + 黄/橙仅作强调，并顺手修掉 `darkMode` 策略 bug。
7. **动效预算 B**：微交互 + 滚动入场 + 页面切换，统一 120/200/320ms 三档与单一缓动，强制尊重 `prefers-reduced-motion`，只动 `transform`/`opacity`。
8. **后台同源但克制**：同一套 token 与几何语言，动效只到 hover/focus/进出场，不放捏捏。
9. **工程收口**：颜色只有一个来源、新增漂移门禁、品牌文案集中、术语与决策写进 GLOSSARY 与 ADR。

最终体验：访问即看到果冻盒 logo 与 JellyBin 字标，页面像一张有立场的图纸而非模板；右下角一颗会呼吸、能被捏的果冻始终在那儿；想用 AI 就捏它一下，面板从它身上长出来，一边读一边问；夜里切暗色，整站变成克莱因蓝的深色版而不是补丁版。

## User Stories

**品牌与标识**

1. 作为读者，我希望页头左侧出现果冻盒 logo 与 JellyBin 字标，而不是一个写着 `BX` 的方块，以便第一眼就记住这个站。
2. 作为读者，我希望 logo 在奶油白背景、克莱因蓝背景和暗色主题下都有清晰的对应呈现，以便任何底色下都不出现发灰或糊掉的方块。
3. 作为读者，我希望浏览器标签页图标在 16/32px 的小尺寸上依然锐利可辨，以便在多个标签之间快速找到本站。
4. 作为中文读者，我希望在英文品牌名旁看到中文「果冻盒」，以便立刻知道这是个中文博客站。
5. 作为分享者，我希望把链接粘贴出去时预览图带官方 logo 与站名，以便分享出去显得正式。
6. 作为维护者，我希望品牌名、字标、助手昵称、版权行只在一处定义，以便以后再改名不用翻十几个文件。

**视觉体系**

7. 作为读者，我希望整站主色是克莱因蓝 + 奶油白，以便视觉上统一、沉静且有辨识度。
8. 作为读者，我希望结构线是 1px 克莱因蓝而不是灰色，以便页面读起来像一张工程图纸。
9. 作为读者，我希望正文区背景有极淡的 40px 网格底纹，以便长文阅读有秩序感又不刺眼。
10. 作为读者，我希望卡片、按钮、输入框是直角而不是大圆角，以便与图纸气质一致。
11. 作为读者，我希望正文用真正加载出来的中文字形（Noto Sans SC），而不是系统字体拼凑出来的字形。
12. 作为读者，我希望长文有合适的行宽（约 68 字符）与行高，以便一篇长文读完不累。
13. 作为读者，我希望包豪斯黄只作为记号笔高亮与几何标记出现，以便重点被强调而不是被染色。
14. 作为读者，我希望珊瑚橙只用于危险/重要状态与主按钮 hover，以便危险信号一眼可辨。
15. 作为读者，我希望页脚是整块克莱因蓝铺色，以便滚动到底时有明确的结束锚点。
16. 作为弱视或色弱读者，我希望所有正文与界面对比度达到 WCAG AA，以便我能读完文章。

**导航与页面**

17. 作为读者，我希望首页是重新编排过的排版（而不是模板三栏），以便一眼看出这个站的编辑立场。
18. 作为读者，我希望首页右栏不再有 AI 卡片，以便右栏专注内容（公告、热门标签、推荐作者）。
19. 作为读者，我希望文章页的目录、阅读进度、正文、评论区层级分明，以便长时间阅读时随时定位。
20. 作为读者，我希望文章列表卡片能一眼区分标题、摘要、标签与统计，以便快速扫读。
21. 作为读者，我希望搜索页的空态与结果页风格统一，以便不觉得"跳到了另一个网站"。
22. 作为读者，我希望用户主页有清楚的画像与收藏/关注分区，以便判断这个人值不值得关注。
23. 作为作者，我希望创作区沿用同一套 token，以便写作时不自相割裂。
24. 作为作者，我希望创作区不出现捏捏，以免与编辑器里的 AI 面板混淆。
25. 作为读者，我希望移动端每个页面都可用（导航、正文、面板、捏捏），以便在路上阅读。
26. 作为读者，我希望明暗切换时不闪白、不跳到另一个排版，以便夜间阅读不刺眼。

**捏捏（Jelly）**

27. 作为读者，我希望右下角常驻一个果冻方块小角色，以便随时知道 AI 在那儿。
28. 作为读者，我希望它闲置时轻微呼吸（4s 一次的 1→1.03 缩放），以便不像死物也不晃眼。
29. 作为读者，我希望悬停时它像果冻被捏一下（横向撑开、纵向压扁再回弹），以便有一点好玩的反馈。
30. 作为读者，我希望点击时它先"被捏"再打开面板，以便动作连贯。
31. 作为新访客，我希望它偶尔弹一句轻气泡提示，以便发现这个功能存在。
32. 作为读者，我希望气泡每个会话最多出现两次（首次进入 + 闲置 90s），以便不被反复打扰。
33. 作为读者，我希望可以把它拖到我偏好的位置，以便不挡住正文或输入框。
34. 作为读者，我希望刷新后它还停在原位，以便不用每次重新摆放。
35. 作为手机读者，我希望它不遮挡正文与输入区，以便小屏也能用。
36. 作为读者，当站点关闭 AI 时，我希望它表现为"睡着"（低饱和、更慢呼吸），点它才告诉我为何不可用，以便我知道这时刻没开而不是坏掉。
37. 作为对动画敏感的读者，我希望它尊重系统的"减少动态效果"，以便不会因为动画而难受。
38. 作为未登录读者，我希望点它时先引导登录而不是弹一个失败面板，以便流程顺。
39. 作为读者，我希望它不遮挡页脚的重要链接，以便我还能找到备案号与关于页。

**AI 面板**

40. 作为读者，我希望面板从捏捏所在的位置生长出来，以便入口与内容感觉是同一个东西。
41. 作为读者，我希望面板打开时捏捏被压成面板右下角的一角把手，以便随时能关掉它。
42. 作为读者，我希望面板不是全屏遮罩，以便我还能看着文章一边提问。
43. 作为读者，我希望回答逐字出现并带打字光标，以便感知它正在思考。
44. 作为读者，我希望可以中途停止回答，以便不浪费每日配额。
45. 作为读者，我希望空状态给出几个可以直接点的问句，以便不知道问什么也能用起来。
46. 作为读者，我希望关闭面板时进行中的请求被中断，以便不产生幽灵回答。
47. 作为读者，我希望对话在开关面板之间保留、且可一键清空，以便连续追问。
48. 作为读者，我希望面板里的错误提示说人话（超时/配额/未启用分别不同），以便知道下一步做什么。
49. 作为读者，我希望面板在手机上变成底部抽屉而不是挤压正文，以便单手可用。

**动效**

50. 作为读者，我希望滚动时内容分级淡入而不是整块弹出，以便节奏自然。
51. 作为读者，我希望页面切换有短暂的过渡，以便不像硬跳。
52. 作为读者，我希望所有动效都短（≤320ms），以便不拖慢阅读。
53. 作为读者，我希望悬停与焦点动效一致，以便交互可预期。
54. 作为读者，我希望开启"减少动态"时全部退化为静态或一次性淡入，以便无障碍。
55. 作为读者，我希望动效不引起布局抖动（不闪烁、不跳位），以便不晕。

**暗色主题**

56. 作为夜间读者，我希望暗色是克莱因蓝铺底 + 奶油白字，以便这是品牌最强形态。
57. 作为夜间读者，我希望站内切换真正控制全站（包括 AI 面板与卡片），以便没有白块补丁。
58. 作为夜间读者，我希望暗色下 logo、字标、图表、目录都清晰，以便不丢信息。
59. 作为夜间读者，我希望原生控件（滚动条、表单、日期选择）也跟随暗色，以便不突兀。
60. 作为新访客，我希望首次访问跟随系统偏好，且之后记住我的选择，以便不用每次手调。

**后台**

61. 作为管理员，我希望后台与读者站共用同一套色彩与几何语言但更克制，以便不觉得它们来自两家公司。
62. 作为管理员，我希望后台浏览器标签有正确的标题与图标，以便与多个标签区分。
63. 作为管理员，我希望表格、表单、弹窗、标签都遵循新 token，以便没有旧青色残留。
64. 作为管理员，我希望动效只出现在 hover/focus/进出场，以便不干扰高效操作。
65. 作为管理员，我希望后台品牌名更新为 JellyBin，以便确认自己在管理同一站点。
66. 作为管理员，我希望登录页与 setup 页有 logo 与字标，以便确认自己在正确的后台。
67. 作为长时间盯表单的管理员，我希望后台文本对比度达标，以便眼睛不累。
68. 作为管理员，我希望后台不出现捏捏，以便工作台保持专注。

**工程与门禁**

69. 作为维护者，我希望颜色只有一个来源（语义 token 层），以便不再在 `:root`、字面 `rgba()`、Naive `themeOverrides` 三处同步。
70. 作为维护者，我希望有门禁阻止新的裸颜色字面量写进组件，以便这次改造不会慢慢退化回硬编码。
71. 作为维护者，我希望两端都由 Tailwind 配置承载色板与 `darkMode: 'class'`，以便类名可用且暗色跟着站内开关。
72. 作为维护者，我希望新增组件能被"组件解析检查"拦住，以便不出现"UI 静默不渲染、lint 全绿"的事故。
73. 作为维护者，我希望新增逻辑有单元测试且既有覆盖率门槛不下降，以便门禁继续有效。
74. 作为维护者，我希望改动分六个阶段提交，以便任何阶段都能单独审查与回滚。
75. 作为维护者，我希望术语与决策落到 GLOSSARY 与 ADR，以便后来者知道为什么这么做。
76. 作为维护者，我希望后端、契约、路由与部署标识一行不改，以便这次重构不引入后端风险。

## Implementation Decisions

**1. 颜色：两层 token，五个色相不扩散**

- 原始层只有五个色相：`blue` `cream` `yellow` `coral` `warm`，命名带品牌前缀，禁止新增第六个色相。
- 语义层是唯一被组件消费的层：底色、次级底色、纸面、墨色、次级墨色、结构线（三档透明度）、高亮底（黄）、危险、危险文字（派生暗橙）、焦点环、阴影。
- 派生规则明确写进 token 文件注释：同色相只动明度/透明度；黄永不做字色；珊瑚橙只在需要 WCAG 对比时用派生暗橙作字色。
- 暗色映射是同一组语义 token 的第二份取值，由 `.dark`/`.theme-dark` 选择器承载；组件不写任何 `dark:` 分支以外的颜色决策。
- 两端各有一份 Tailwind 配置，承载五个色相与语义色类名，并设 `darkMode: 'class'`（同时修掉现有"开关管不住 `dark:`"的 bug）。

**2. 形状与排版语言**

- 默认圆角 0；仅头像、胶囊标签、捏捏本体用全圆角。Naive UI 的全局圆角覆盖同步改为 0。
- 形状语义固定：三角 = 包豪斯黄（装饰与编号标记）；方 = 珊瑚橙（状态/危险）；圆 = 克莱因蓝铺色块（页脚、统计数字底、章节锚点）。
- 结构线一律 1px 克莱因蓝，三档透明度表达层级，不使用灰线；40px 网格底纹只用暖灰、透明度极低，仅出现在内容区与侧栏背景。
- 英文继续用已有的自托管 Sora（含既有度量匹配 fallback）；中文新增 Noto Sans SC 的 `@font-face` 加载（依赖已在，只是从未加载），同样配度量匹配 fallback 与 `font-display: swap`。
- 正文行宽固定约 68 字符、中文正文行高 1.75；标题字重 700 与轻微负字距。

**3. 动效体系**

- 只引入 `motion-v`（当前版本线 2.x，其 Nuxt 模块对 Nuxt 4 兼容），**只装在读者站**；后台不引入，用 CSS 过渡 + Naive 内建过渡。
- 统一三档时长 120 / 200 / 320ms 与单一缓动曲线，列表 stagger 40ms；只动 `transform` 与 `opacity`。
- 全局尊重 `prefers-reduced-motion`：动效退化为无动画或一次性淡入；捏捏退化为静态贴片。
- 接入注意：`AnimatePresence` 的退场动画与 `useScroll`/`useInView` 这类客户端钩子必须在客户端挂载守卫内使用，并保留 `vite.ssr.noExternal` 作为生产构建的兜底。
- 页面切换过渡只做淡入 + 极轻微位移，不做转场动画。

**4. 品牌：单点定义 + 双套 logo**

- 新增品牌模块（两端各一份），导出：英文名、中文名、字标结构（英文大字标 + 中文小字副标）、助手显示名、站点一句话介绍、版权行。所有硬编码品牌串（读者站 12 处、后台 4 处）改为消费它。
- logo 资产双套：
  - 高清套：用户提供的 3D 果冻盒渲染（透明 PNG/WebP），用于 ≥48px、OG/社交预览与登录页；
  - 矢量套：新绘制的**扁平几何果冻方块** SVG（克莱因蓝填充 + 奶油白 1px 结构线 + 一小块包豪斯黄高光），用于 16/32px favicon、`apple-touch-icon`、mask icon，以及捏捏本体的形状来源。
- 字标用字体排版实现（Sora 700 + 中文副标），不依赖图片里的文字。
- 后台补齐 `app.head`：title、description、`lang="zh-CN"`、icon、OG；登录页与 setup 页改用字标 + logo。
- 保留既有内部标识不变：`blogx-theme` cookie、`blogx_access_token`、`blogx_profile_snapshot`、`BLOGX_*` 环境前缀、容器/服务名。新增的存储键用中性新名（`jelly:launcher-position`、`jelly:bubble-count`）。

**5. 捏捏（Jelly）组件与它的状态机**

- 两个新模块：一个果冻角色组件（只负责外观与指针交互）+ 一个状态 composable（唯一的状态真相源）。
- composable 暴露的接口（对外可观察）：
  - 状态：是否可用（AI 总闸 + 条目启用）、面板是否打开、当前气泡、持久化位置、是否处于减少动态、消息列表、是否流式进行中。
  - 动作：打开、关闭、切换、拖到新位置、关掉气泡、发送、停止、清空。
  - 副作用边界：它只调用既有 AI 服务层的流式函数，不直接发请求。
- 视觉状态机（角色表现）：`idle`（4s 呼吸 1→1.03）→ `hover`（挤压回弹）→ `press`（先压再触发）→ `open`（压成面板右下角把手）→ `dragging`（轻微滞后跟随）→ `disabled`（低饱和、更慢呼吸，点击只说一句"AI 还开着小差"）。
- 出现规则：读者站渲染，创作区路由前缀下不渲染；移动端降低尺寸并避让输入框。
- 气泡节奏：首次进入一次，闲置 90s 再一次；每会话最多 2 次，计数写 session 存储；点击即关闭气泡。
- 位置持久化：拖拽结束后写本地存储，恢复时做视口边界钳制。
- 无障碍：可键盘聚焦、回车/空格触发、有 `aria-label` 与 `aria-expanded`；减少动态时无呼吸动画。

**6. AI 面板：从捏捏身上生长**

- 替换现有居中模态式 AI 对话组件；首页右栏 AI 卡片整体删除（入口只剩捏捏）。
- 面板形态：桌面从右下角以 `transform-origin` 朝左下生长、宽约 420px；移动端为高约 78vh 的底部抽屉。非遮罩、可同时阅读正文。
- 面板打开时捏捏变为面板右下角把手（同一元素、同一位置），关闭时回弹复位。
- 能力保留：`POST /api/ai/search/llm` 的 SSE 流式、最近 6 轮历史、关闭时中断请求、停止回答、清空对话、登录过期时刷新会话重试。
- 新增：流式打字光标、空状态四个快捷问句、按错误类型分化的文案（超时/配额/未启用）、消息进出场的轻柔过渡。
- 后端契约无变化，不新增接口。

**7. 后台：同源、克制、补 head**

- 重写 Naive 主题覆盖：主色克莱因蓝、hover/按下用派生明度、危险用珊瑚橙、圆角 0、字体栈含中文 fallback。
- 后台样式层统一改为消费语义 token，消灭三处同步；保留其 `app/utils` 纯逻辑层的可测性。
- 只做 CSS 过渡与 Naive 内建过渡，不接 motion 库，不放捏捏。
- 补齐 `app.head`；品牌串改为品牌模块；菜单文案与路由不变。

**8. 门禁与收口**

- 新增"设计 token 漂移"测试：扫描两端 `app/**` 的组件与样式，除 token 文件、品牌标志矢量、OG 生成物之外，禁止出现裸十六进制/`rgba()` 颜色字面量；违例直接失败并打印文件与行号。
- 既有"组件解析检查"继续跑在新的组件上（它会拦住 `<JellyXxx>` 这类解析不到的标签）。
- 六个提交阶段：(1) 地基（token、Tailwind 配置、字体、动效接入）(2) 品牌（logo/字标/favicon/OG/改名）(3) 读者站页面重排 (4) 捏捏 + AI 面板 (5) 后台 (6) 打磨 + 暗色 + 文档。

**9. 无 schema / 无契约变更**

不改数据库、不改 OpenAPI 契约、不新增 API、不改路由与 URL、不改部署标识。

## Testing Decisions

**什么算好测试**

只测对外行为，不测实现细节：composable 暴露的状态与动作序列、纯函数的返回值、门禁脚本对文件的判定结果。不写"断言某个 CSS 类名存在""断言 DOM 里某个 div 的 class"这类与视觉实现耦合的测试——那会让每次调样式都改测试。

**要测的模块**

- **捏捏状态 composable（新增，主要战场）**：可用/不可用（AI 总闸关闭、条目未启用）、打开与关闭、关闭时中断进行中的流式、气泡节奏的会话上限与闲置触发、位置持久化的写入与视口钳制恢复、减少动态开关的取值。以假的服务层与非假的存储注入验证，不触碰真实网络。
- **品牌模块（新增，两端各一）**：中英名、字标结构、助手昵称、版权行、以及"标题为中文、字标为英文"的取值契约；后台那份恰好落在后台既有的 `app/utils/**` 高门槛内。
- **设计 token 漂移门禁（新增）**：构造一个含裸色值的假组件断言失败、构造合规文件断言通过（门禁自身的"永远不会红"风险必须被覆盖）。
- **既有 AI 流式服务层（不改）**：现有用例必须继续通过——捏捏与面板都复用该服务层，网络接缝保持不变。

**先例**

- composable 状态机测试：写作区 AI 助手那组用例（23 用例，注入假服务层、断言状态转移与中断）；
- 服务层 SSE 测试：AI 流式服务那组用例（假流式响应块）；
- 纯函数测试：头像/格式化等 `utils` 用例；后台的角色与文案用例；
- 门禁测试：`scripts/check-components.mjs` 的做法（把"编译看不出来"的问题做成可失败的门禁，并给自己造人造违规用例）。

**门槛不降**

读者站维持 60/50/66/60，后台维持 `app/utils/**` 95/90/95/95；新增模块必须带用例，否则门禁会红。`passWithNoTests` 保持 `false`。

**验收方式（无后端）**

两个前端本地起义（端口 3000 / 3001，后端 8080 不起），接口失败时以空态/降级态截图；AI 面板的流式用本地假流验证打字、停止、关闭中断、错误文案。真实流式的端到端回归留待后端可用时补一次。

## Further Notes

**风险（按影响排序）**

1. **直角化是最大的一处审美赌注**：圆角归零 + 1px 线在大屏上容易做成"工程稿"而不是"博客"。缓解：奶油白大面积呼吸 + 长文排版优先 + 重点页逐页目视调，必要时把圆角作为可回调的单一 token。
2. **Naive UI 深改会波及所有组件**：表格、弹窗、抽屉、日期选择都读全局圆角与主色，需逐页目视回归；后台尤其明显。
3. **`motion-v` 与 SSR**：`AnimatePresence` 退场与客户端钩子在 SSR 下要守卫，生产构建可能需要 `ssr.noExternal` 兜底；若接入成本失控，动效可退回到纯 CSS 过渡（decision 6 的语义不变）。
4. **颜色迁移量**：读者站有约 42 行 `rgba()` 的青绿族 + 27 行边框族 + 20 行阴影族，后台约 30 处 `rgba()`；迁移必须靠 token 替换而非逐处手改，否则必然漏。
5. **无后端 = AI 只能验交互**：真实流式、配额、登录刷新路径在后端可用时需回归一次。
6. **门禁新红可能来自旧代码**：漂移测试首次运行会把既有硬编码全部点亮，需以"改造中逐文件收敛 + 最终必须为 0"的方式接入，不能一开始就要求全绿（否则只能关掉它）。
