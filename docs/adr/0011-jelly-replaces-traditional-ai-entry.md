# ADR-0011：捏捏（Jelly）常驻角色取代传统 AI 入口

- 状态：已接受
- 日期：2026-10-30
- 来源：issue #1（JellyBin 双前端视觉体系重构 spec）与 issue #14（文档落档）；落地分票 #9（角色与状态 composable）→ #10（AI 面板）

## 背景与问题

读者站现在只有一个 AI 入口：首页右栏 AI 卡片里的"进行对话"按钮，点开是居中 `980px` 的白色 `NModal`。它的问题是结构性的：

- **入口与内容分属两个空间**：入口只在首页；在文章页读到一半想提问，要么回首页、要么开新标签，没法"边读边问"。
- **是补丁而不是体系**：对话框 scoped CSS 全部写死 `#ffffff !important`（切暗色像一块白补丁）、气泡恒带 1px 边框、零过渡、只有 `animate-spin` loader、无打字光标、无空状态引导。
- **交互细节缺失**：错误提示不区分超时 / 配额 / 未启用，读者不知道下一步该做什么。
- **AI 在页面上"看不见"**：除了首页那一个按钮，读者无从知道这里有 AI、是否开着。

用户要的是一个**一直在那儿的东西**：右下角一颗会呼吸、能被捏的果冻方块；想用 AI 就捏它一下，面板从它身上长出来。

## 决策

1. **常驻角色**：读者站右下角渲染 Jelly（捏捏）果冻方块角色；创作区 `/studio/**` 不渲染；移动端降低尺寸并避让输入框与正文；可拖拽，拖拽结束后位置写本地存储（`jelly:launcher-position`），恢复时做视口边界钳制。
2. **面板从角色身上生长**：打开时捏捏被压成面板右下角的把手（同一元素、同一位置），关闭回弹复位；桌面从右下角以 `transform-origin: 100% 100%` 生长、宽约 420px，**非遮罩**，可同时阅读正文；移动端为高约 78vh 的底部抽屉。
3. **状态唯一真相源**：角色组件只负责外观与指针交互；状态与动作（可用性、面板开合、气泡、位置、减少动态、消息列表、流式进行中）收在一个 composable 里。它只调用既有 AI 服务层的流式函数，不直接发请求。
4. **保留既有能力**：SSE 流式（`POST /api/ai/search/llm`）、最近 6 轮历史、关闭时中断请求、中途停止、清空对话、401 后刷新会话重试。后端契约不新增、不改。
5. **补齐交互**：流式打字光标、空状态 4 个可直接点的快捷问句、按错误类型分化的提示文案（超时 / 配额 / 未启用）。
6. **可用性表达**：AI 总闸关闭时表现为"睡着"（低饱和、更慢呼吸），点击只说明"AI 还开着小差"；未登录时先引导登录，而不是弹一个失败面板。
7. **气泡节奏**：首次进入一次，闲置 90s 再一次；每会话最多 2 次（sessionStorage `jelly:bubble-count`），点击即关闭。
8. **无障碍**：可键盘聚焦、回车/空格触发、带 `aria-label` 与 `aria-expanded`；`prefers-reduced-motion` 时退化为静态贴片。
9. **删除旧入口**：首页右栏 AI 卡片整体删除（入口只剩捏捏），旧的居中模态组件不再使用。
10. **后台不放捏捏**：后台 AI 仍在设置、日志等功能页；工作台保持专注，不出现角色。

## 理由与已否决方案

入口与内容同源是这个决策的核心：捏捏不是"换个皮肤的对话按钮"，它本身承担状态表达（闲置 = 可用、睡着 = 关闭、被压成把手 = 面板开着），读者用同一个东西记住"AI 在哪、开没开、能不能用"。非遮罩软面板则保住了长文阅读场景下"边读边问"这个唯一真正有价值的用法。

已否决的方案：

- **只换入口（把首页 AI 卡片换个样式/按钮，对话框仍是居中模态）**：入口仍然只在首页，文章页想提问还是要跳回；对话框与文章仍是两套空间，白块、无过渡、无空状态这些补丁会原样留下。
- **全屏遮罩（点开铺满屏幕的对话层）**：遮罩切断了"边读边问"，开/关是硬切换；移动端直接压正文；与长文阅读优先冲突。
- **独立 FAB（右下角一个普通浮动按钮，面板从按钮旁弹出）**：FAB 是通用 SaaS 语言，没有角色、没有状态表达；"睡着"与"被压成把手"都无处安放；入口与内容只是相邻，不是同源。
- **保留首页 AI 卡片作为第二入口**：入口分裂成两套（两套状态、两份历史、两套关闭语义），读者需要先判断"该点哪个"。

## 代价 / 不做什么

- **常驻角色要处理避让**：右下角会挡住正文、输入框与页脚链接；拖拽与位置恢复要做视口钳制，移动端要单独设计尺寸与位置。
- **状态机复杂度上升**：六态（`idle` / `hover` / `press` / `open` / `dragging` / `disabled`）叠加可用性、气泡节奏、位置持久化、减少动态，状态 composable 因此成为本次的主要测试战场（只测对外行为，不测样式实现）。
- **非遮罩面板要共享页面空间**：与页面滚动、z-index、键盘焦点共存；面板打开时捏捏仍是同一元素，角色与面板的定位相互耦合，不能各自独立移动。
- **首屏多一个常驻元素**：对性能与布局稳定性（不抖动、不闪）有要求，动效降级必须同步到位。
- **无后端只能验交互**：流式用本地假流验证打字、停止、关闭中断与错误文案；真实流式、配额、登录刷新路径留待后端可用时回归一次。
- **不做什么**：后台捏捏、e2e / 视觉截图比对、新接口或契约变更、多语言、把后台 AI 入口改成角色。

## 当前生效约束

1. 读者站 AI 的唯一入口是捏捏；首页右栏 AI 卡片与居中模态不得恢复。
2. 捏捏只在读者站渲染，`/studio/**` 不渲染；后台不出现捏捏。
3. 状态唯一真相源在 composable；角色组件不得自行发请求或另存状态。
4. 面板必须是非遮罩软面板（桌面右下角生长、移动端底部抽屉），不得改成全屏遮罩。
5. 关闭面板必须中断进行中的流式请求。
6. 新增存储键用中性名（`jelly:launcher-position` / `jelly:bubble-count`）；既有 `blogx_*` 键与 `blogx-theme` cookie 不改名。
7. 全部动效与角色表现强制尊重 `prefers-reduced-motion`；减少动态时捏捏退化为静态贴片。
8. 复用既有服务层 `frontend/app/services/ai.ts`；后端契约与接口不变。
