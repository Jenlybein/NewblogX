## v2 开场：修掉「架构改完之后功能失效」

用户报的三个现象：发文章后在首页/个人主页看不到、点赞按钮一直转圈。
全部定位并修复，已部署到线上（首尔实例）验证通过。

### 根因一：CDC 全量转储失败（文章列表空）
- 已在上一轮修掉（bad277c）：alpine 上 `apk add mysql-client` 装到的是 MariaDB 客户端，
  `mariadb-dump` 在 canal 固定的 `--skip-opt` 下会下发 MariaDB 独有的 `sql_mode`
  （NO_KEY_OPTIONS 等），MySQL 8 报 1231 → dump exit 2 → canal 起不来 → river 静默死。
- 修复：wrapper 摘 `--skip-opt` + `skip_master_data` 改 false + 把 `cmd/cli` 编进镜像。

### 根因二：刷新令牌自等待死锁（点赞转圈）
- `refreshSession()` → `fetchCurrentUser()` → `getSelfUserDetail()`（默认鉴权）→
  判成鉴权失败 → `refreshSession()` → 返回同一个未完成的 `refreshPromise` → **P 等 P**。
- `finally { refreshPromise = null }` 永不执行 → 会话被永久毒化 → 按钮永远转圈且不报错。
- 修复：`getSelfUserDetail` 支持 `retryAuth`；刷新后校验资料传 `retryAuth: false`；
  刷新请求补 15s 超时（它走裸 `$fetch`，绕过了 `withRequestTimeout`）。
- **诚实的边界**：环是结构上必然存在的（已消除 + 有测试），但「就是那次卡住的原因」未证实。

### 本轮新增：让「静默失效」不再静默
- `internal/platform/health` 注册表 + `/health/ready`（`/health` 保持存活语义不动）。
- `scripts/verify-deploy.sh`：部署后必须 `healthy:true` **且** `cdc_river` 是 `running`
  （只看 healthy 不够：`disabled` 也是 healthy）。

### 关键排查手法（值得复用）
- **用公开写接口做对照实验**：`POST /articles/view` 让 `view_count` 1→2，证明 Redis 计数
  链路通 → 反证点赞请求没到后端。比读十遍代码快。
- **先确认「错误会不会被吞」**：`search/app.execute` 在 `!resp.Success` 时返回 error，
  所以 `code:0`+空列表 = 真的没文档。

- 主动推翻的两个「完美假设」：运行时配置缓存为空、新建文章 visibility 写空串。

## C1 完成：运行时配置从「一段两列」改成「一段一行 JSON」

配置分层第三层（管理员可改）从 `runtime_site_config_models(site_json, ai_json)`
换成 `runtime_config_models(name, payload)`，七个段：site / ai / mail / storage /
oauth / log / upload。**一段一行**而不是列化，理由是零 DDL 硬约束（见下方教训）。

### 关键设计
- `internal/platform/config/merge.go`：JSON 深度合并。规则三条 ——
  `null` 不覆盖、两边都是对象递归、其余 override 胜出（**数组整体替换**，
  逐元素合并会让"删白名单项"永远删不掉）。这是「加字段零迁移」的地基。
- `decodeSection[T]` / `decodeOrDefault[T]` 写成**包级泛型函数**（Go 方法不能带类型参数）。
  单段解析失败只 warn + 回退该段默认值，不 panic：配置坏了该降级，数据库连不上才该拦启动。
- `snapshotLocked()` 返回副本：调用方拼响应时会把密钥换成占位符，给指针会让"读"变"写"。
- `conf.Mail` 替代 `conf.Email`（腾讯云 SES，模板发信，Region 仅 ap-guangzhou / ap-hongkong）。

### 本轮抓到的三个真 bug（都不是我新写的代码引入的）
1. **软删除 + 唯一索引 = 永久 500**：`upsertPayload` 用默认 scope 查，看不见
   `deleted_at` 非空的行 → 走 INSERT → 撞 `name` 唯一索引。同理会**让启动直接失败**
   （`seedMissing` 也 Create）。修法：查询带 `Unscoped()`，查到软删除行就恢复
   （`deleted_at` 置空）+ 写新值；`seedMissing` 改走 `upsertPayload` 复用同一逻辑。
2. **旧代码有个「修 bug 的 bug」**：库里 `SiteInfo.Title` 为空时把**整段站点配置重置回默认值**
   —— 意味着每次重启都丢掉管理员配的站点设置，为的是掩盖「旧行字段少」。
   按字段合并已经根治了那个问题，这个分支必须去掉，否则后台配置永远存不住。
3. **默认值解析失败时回退成全零**：`site_default_settings.yaml` 里全是 `${BLOGX_*}`，
   envyaml 缺任一环境变量就整份拒绝解析。原来回退到 `conf.RuntimeDefaults{}`
   会让上传白名单变空数组、日志级别变空串。改成回退到 `settings.yaml` 的基线值
   （`qiniu`/`qq`/`upload`/`log` 那里是有的；`site`/`ai` 本来就没有，所以旧代码回退的也是零）。

### 顺手做的
- 删掉 `deploy/docker/api/config/`（死副本：Dockerfile 拷的是 `/build/backend/config`，
  compose 挂的是 `backend/config`，全仓零引用）。它已经和 `backend/config/` 漂移了
  （`skip_master_data`、`mysqldump` 路径、缺 `outbox` 段），留着必被改错。
- `conf.Upload` 删掉 `Size` / `UploadDir`（全仓零读取）。
- archcheck R12 给 `conf.Mail.TemplateID` 加了点名豁免（SES 模板编号，控制台分配的小整数，
  类型由 SDK 的 `*uint64` 决定），并补了规则单测。

### 教训
- **「能加表不能改表」决定了表形态**：一开始想列化（一个设置一列），被零 DDL 红线否掉；
  中间又倾向「一段一行」，最后查大厂做法时发现 GitLab 官方文档现在也推荐 JSONB 而非列化
  （"往已有 JSONB 列加设置不需要 DB review"）。**先查清约束，再谈优雅**。
- **测试夹具与进程级单例冲突**：`testutil.DB()` 只有一个槽位，同一用例里建两次引擎会读到
  上一次灌进去的运行时配置行，表现为"配置改了不生效"。夹具里显式清表即可。
- **`go test ./...` 的日志噪音也是信号**：`Take` 找不到行时 gorm 会刷 `record not found`，
  而这些是启动时的正常路径 → 换 `Find`。

### 部署后后台白屏（60a02ed）
现象：重建 `blogx_admin` 后 `https://gentlybeing.cn/admin/` 一片空白，服务端日志全 200。
取证：`deploy/state/nginx/logs/access.log` 里能看到用户浏览器拉的是**上一版** chunk
（`3Htzi6Dk.js` / `z6FHKie_.js`），而新 HTML 的 entry 是 `Cjqh0S7D.js`。
根因：Nitro 对 index.html **不返回 Cache-Control**，nginx 只做纯代理，浏览器走启发式
缓存 → 复用旧 HTML → 旧 HTML 引用的入口 chunk 已换名 → 404 → SPA 挂不上。
修法：nginx 模板加三层——
`^~ /admin/_nuxt/` 与 `^~ /_nuxt/` → `public, max-age=31536000, immutable`；
`^~ /admin/` 与 `/` → `no-cache`；两处都 `proxy_hide_header Cache-Control` 防重复头。
**注意 nginx 的 access.log 不在 `docker logs` 里**，挂在 `deploy/state/nginx/logs/`，
查 4xx/白屏只能看那个文件。
**教训**：前端产物换代 + 浏览器缓存 = 白屏且服务端无错。判断口诀是"日志全 200 但页面空"，
先比 HTML 里的 chunk 名与 Network 里实际请求的 chunk 名是否一致。

## 后台"添加配置成功但列表一直空" —— 读写分离 + 写完立刻读（2026-10-29 傍晚）

症状：`POST /api/ai/providers` 200、库里确实有那行，但 `GET /api/ai/providers`
恒返回 54 字节（空列表），刷新页面、重新登录都不变。

根因：**线上是 gorm dbresolver 读写分离**（`backend/core/init_db.go:136`，
`Sources` = mysql-master，`Replicas` = mysql-slave，`RandomPolicy`），普通读默认
落到从库，而复制是**异步**的。`ProviderService` 每次写完都 `reload` 重建内存
快照 → reload 查从库（那行还没复制过去）→ 读到空 → **把快照覆盖成空**，此后
没有任何路径再刷新它。AI 调用读的就是这份快照，于是永远"没有启用的模型配置"。

修法：`ProviderRepo.List`/`Get` 显式 `Clauses(dbresolver.Write)` 钉主库。
这张表是个位数行的后台配置，AI 调用读内存快照不查库，钉主库没有压力。

**通用教训**：全仓只有 `core/init_db.go` 一处注册 resolver，**没有任何一处用
`dbresolver.Write`**。所以凡是"写完立刻读回"的路径（reload / 回读校验 / 写后
返回实体）都可能被复制延迟坑掉，且症状是"静默空数据"而不是报错。以后碰到
"写成功但读不到"，第一件事就是确认这条读走了哪个库。

守卫：`TestProviderRepo_ListReadsPrimary` 用两个独立内存 sqlite 模拟主从
（sources 写入、replicas 永不写入），断言"写完立刻读必须读到"。
去掉 Write clause 该用例立刻红（已实测），**不用起 Docker** 就能防回归。

## AI token 用量日志（2026-10-29 晚，提交 5a6c5b6）

用户要求：「ai token 使用量也要进入日志，后台可观测 token 使用量」，并要首页能看
今日 / 周 / 月 / 年，**≤20 个 x 轴点用柱状、>20 用折线**。

### 用量从哪来（改造前后的盲点）
eino 把用量放在 `schema.Message.ResponseMeta.Usage`。改造前两处都扔掉：
非流式只取 `reply.Content`；流式 `chunk.Content == "" { continue }` 正好跳过
OpenAI 系在 EOF 补发的「空正文 + 只挂 usage」收尾帧。
现在 `platform/llm` 有 `ChatDetailed` / `ChatStreamDetailed(..., onDone)`，
`Chat`/`ChatStream` 退化成薄包装（11 个原单测零改动）。

**两个只有 -race 才会暴露的坑**：
1. **流式回调的 defer 顺序**。回调必须排在 `close(contentChan)` **之前**执行，
   否则调用方 `for range` 读到通道关闭时用量还是零值。注册顺序要写成
   `defer close(content); defer close(err); defer callback`（LIFO 后注册先执行）。
   不跑 `-race` 时它随机通过 —— 别用普通 `go test` 验证这类代码。
2. **格式串混用**：`%Y-%m-%d` 是 ClickHouse 的写法，Go 的 `time.Format` 用
   `2006-01-02`。混成一个常量后所有桶键都变成字面量 `"%Y-%m-%d %H:%M:%S"`，
   查得到数据也对不上且不报错。桶单测当场抓住了它。

### 记账链路
`ai.CallMeta` 走 ctx（`WithCallMeta`）：scene 在 `app/service.go` 各用例入口打
（SearchLLM 一个请求连调 rewrite+answer，按端点打标会把两者混成一个）；
user_id/request_id/trace_id 在 `adapter/http/handler.go` 的 `callCtx(c)` 打。
上报出口是包级 `ai.SetCallReporter`，由 `app/WireAI` 装一次，nil 空转。

日志：新增第 6 类 `KindAICall` → CH `ai_call_logs` + 每日文件。5 处开关同步
（Kind / 目录表名 / kindCount+routes / logSubDirs / 预热目录）。
CH 表故意与别人不同：**TTL 400 天**（首页要「本年」，120 天会抹掉前 8 个月）、
**ORDER BY (ts, scene, event_id)**（查询全带时间窗）。
不记 prompt 与正文：32KB 上限是整条丢弃，且正文属于用户内容。

### 查询与前端
- `GET /logs/ai`、`GET /data/ai-usage?range=today|week|month|year`。
- 桶在 Go 里生成（`ai_usage_buckets.go`，`now` 注入以便单测钉闰月/跨年/周一），
  缺的补 0；聚合带 **`FINAL`**（WAL 重放会重复，列表能容忍、加总不行）。
- 时区：CH 侧 `formatDateTime(...,'Asia/Shanghai')` + Go 侧 `FixedZone(+8)`。
  容器 TZ 是 UTC，用 `time.Local` 会让今日曲线偏 8 小时且不报错。
- 前端不引图表库：柱复用 `.admin-chart` CSS，折线是自绘 SVG
  （`preserveAspectRatio=none` 必须配 `vector-effect=non-scaling-stroke`）。
  形态判定与数字格式化在 `app/utils/aiTokens.ts`（覆盖率只统计这里）。
