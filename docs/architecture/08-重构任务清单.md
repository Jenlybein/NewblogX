# 08 · 重构任务清单（执行版）

> 这是"照着做"的清单：**任务、依赖、验收命令**。为什么这么做见 [04](./04-迁移路线图.md)、[06](./06-质量保障与治理.md)、[07](./07-日志模块治理.md)。
> 目标：每一步都能编译、能上线、能回滚；不接受"看起来做了"。

---

## 0. 执行纪律

1. **一个任务 = 一个可独立 review 的 commit**（或小 PR）。任务 ID 写进 commit message，例如 `S1.2: ci run go test -race`。
2. **每个任务必须有"验收命令"**，跑不过不算完成。
3. **先 `--warn` 后 `--error`，先新增后删除**：新结构跑通再删旧代码。
4. **任何阶段结束都必须能编译、能上线**；主干始终可发布。
5. **不做大爆炸重写**：article 先试点，验证模式后再批量。

## 2. M1 建闸（第一步，先做这个）

> 为什么先做：R0 刚搬完目录，必须先证明"搬完还能编译"；且现有 2,357 个断言从未自动执行。没有基线，后面无法判断对错。

### S1.0 基线校准 ★ 第一步

| 步骤 | 命令 | 期望 |
| --- | --- | --- |
| 1. 确认工具链 | `go version` / `node -v` / `pnpm -v` | Go ≥1.25、Node ≥22、pnpm ≥10 |
| 2. 后端编译 | `cd backend && go build ./...` | 通过；若失败，记录首个错误（R0 搬目录的残留） |
| 3. 后端测试基线 | `cd backend && go test -count=1 ./... 2>&1 \| tee /tmp/baseline-test.txt` | 记录 pass/fail/skip 数量 |
| 4. 前端类型 | `cd frontend && pnpm install --frozen-lockfile && pnpm typecheck` | 记录错误数 |
| 5. 管理端类型 | `cd frontend_admin && pnpm install --frozen-lockfile && pnpm typecheck` | 记录错误数 |
| 6. 产出基线 | 写 `docs/architecture/baseline.md` | 数字可复查 |

**验收**：`docs/architecture/baseline.md` 存在，包含"编译通过/失败、测试 pass/fail/skip、两端 typecheck 错误数"。
**若 `go` 不在 PATH**：先装 Go 1.25（scoop 或官方包），再继续——这是整个重构的前提。
