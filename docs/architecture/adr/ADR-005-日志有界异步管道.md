# ADR-005：日志改为有界异步管道 + 类型化事件

## Status

**Proposed**（2026-10-24）

## Context

现状日志链路的五个病灶（证据见 [07 §1](../07-日志模块治理.md)）：

1. `utils/logsafe/sanitize.go:52` 对任意 `any` 做反射 + `json.Marshal`，遍历无深度/大小上限
2. `write_action_audit.go:49` 的 `RequestBody any` / `ResponseBody any` 允许整对象进入
3. `write_sink.go:25` 在请求路径**同步** `json.Marshal` + 全局锁 `file.Write`
4. `log_base.go:54`、`init_logrus.go:42` 每条日志调 `NextSnowflakeID()`
5. `fluent-bit.conf:12` 5 个 tail、`Mem_Buf_Limit` 10–20MB、`Skip_Long_Lines On`（丢）、`Read_from_Head On`（重）

结果：并发一高就内存尖刺、RT 抖动；ClickHouse 慢时丢日志且不可见。

## 备选方案

### A. 保留 logrus + 文件 + fluent-bit，只修截断

- 修 `SanitizeValue` 的深度/大小上限，`SetReportCaller(false)`，去掉雪花 ID。
- 优点：改动最小。
- 缺点：**同步写在请求路径**没解决；`any` 仍然存在；fluent-bit 的丢/重仍然存在。
- 判断：**治标不治本**。

### B. logrus + 异步 Hook（缓冲 channel）+ 文件 + fluent-bit

- 给 logrus 加一个 bounded channel hook，后台写文件。
- 优点：请求路径不阻塞；改动中等。
- 缺点：`any`/反射/审计整对象仍在；fluent-bit 仍是单点丢/重；无法做"审计不丢"的差异化策略。
- 判断：**半成品**。

### C. 自建类型化 Emitter + 有界队列 + 批量直写 ClickHouse + WAL（推荐）

- 封闭字段类型；`Emit` O(1)；单写协程批量；失败落 WAL 重放；去掉 fluent-bit 的 app tail。
- 优点：六条硬约束全满足；审计可做到不丢；日志管道自身可观测。
- 缺点：要写约 1200 行基础设施（Emitter/Writer/WAL/Replayer/ClickHouse sink）；运维多一个 WAL 目录。
- 判断：**采用**。

### D. OpenTelemetry Collector + OTLP

- 应用发 OTLP logs 到本地 collector，collector 批量写 ClickHouse。
- 优点：标准协议、厂商中立、trace/log 统一。
- 缺点：引入 collector 运维；字段模型要映射到 OTel LogRecord；短期成本高于 C。
- 判断：**保留为 C 的导出器选项**（Emitter 可加一个 OTLP exporter），不在本次强制。

## Decision

**采用 C。** 同时让 D 成为可选导出器——`log.Emitter` 面向"记录"而非具体后端，后端可以是 ClickHouse / file / OTLP。

关键取舍：
- **runtime 可丢，audit/login 不可丢**：队列满时 runtime 丢弃并计数，audit 落 WAL。这是"业务稳定优先"的显式选择。
- **不做全量调用栈**：生产默认关闭 `ReportCaller`，仅 error 采样抓栈。
- **去掉 fluent-bit 的 app 日志采集**：它继续采集容器 stdout/stderr 与基础设施日志，但业务日志由应用直写，消除"丢/重"单点。

## Consequences

### 变好的

- 内存有硬上限，RSS 不再随日志量线性增长
- 请求路径零序列化/零磁盘/零网络
- 类型化事件让"传结构体"在编译期/archcheck 期被拦住
- 审计不丢（WAL + 幂等键）
- 日志管道自身有指标，丢了多少一目了然

### 变差的

- 新增约 1200 行基础设施代码与一个 WAL 目录
- ClickHouse 写入需要批量大小/超时/退避调参
- 需要一次性迁移 5 类日志的写入调用点

### 需要跟进的

- WAL 目录的磁盘配额与清理策略（积压 >256MB 告警）
- ClickHouse 表 TTL 按类调整（runtime 30d / audit 180d）
- 若未来上 OTel，增加 `otlp` exporter，不改业务侧

## 验证

```bash
# 1. 类型封闭：日志字段不得出现 any / 结构体
( cd backend && go run ./tools/archcheck --rule=log-no-any --error ./internal/... )

# 2. 请求路径无序列化/磁盘
( cd backend && ! grep -rn "json.Marshal\|os.OpenFile" internal/platform/log/emit.go )

# 3. 有界：1 万 QPS 压测 1 分钟，RSS 平稳；log_dropped_total 有值
# 4. 不丢：断 ClickHouse 写 1000 条 audit，恢复后 count==1000 且无重复
```
