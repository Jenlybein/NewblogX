# ADR-006：测试体系改为金字塔 + testkit + 有状态 fake

## Status

**Proposed**（2026-10-24）

## Context

现状（证据见 [06 §1](../06-质量保障与治理.md)）：

- 117 个 Go 测试文件、2,357 处断言，但 `t.Parallel()` 只有 **3** 处
- 测试普遍依赖 `testutil.InitGlobals` / `Deps` / 包级全局，**无法并行、无法隔离**
- 集成测试用 SQLite 模拟 MySQL，`ON CONFLICT` / `clause.Locking` / JSON 函数行为不同 → **假安全**
- `repository/` 449 行核心 SQL **0 测试**；`frontend_admin` **0 测试**
- 无 CI，2,357 个断言从不自动执行
- 契约（openapi）无人消费，前端 1,005 行类型手写

同时，业务规则散在 handler 的 `if` 里，domain 层不存在，导致"想测规则就得起 HTTP + 真库"。

## 备选方案

### A. 维持现状，只加覆盖率

- 优点：零改造。
- 缺点：结构不变，测试仍然不能并行、不能隔离；覆盖率数字可以刷，但规则仍无人守。
- 判断：**自欺**。

### B. 在现有风格上补更多集成测试

- 优点：贴近真实链路。
- 缺点：每个"状态 × 角色"组合都要起一次环境，成本高到没人写；必然退化为只测 happy path。
- 判断：**数量上去了，质量没上去**。

### C. 金字塔 + testkit + 有状态 fake + golden/契约（推荐）

- domain 纯单测穷举规则；app 用 fake 端口测编排；adapter 用真库测 SQL；HTTP 测契约；E2E 只保主链路。
- 优点：快、可并行、确定、规则有唯一落脚点；契约漂移在编译期暴露。
- 缺点：需要先做架构重构（domain/app/adapter + 端口注入）；要写 testkit 与 fake（约 800 行）。
- 判断：**采用**。

### D. 只做 E2E

- 优点：最接近用户视角。
- 缺点：慢、脆、定位难，无法穷举规则组合。
- 判断：**只作为金字塔顶端的一小层**。

## Decision

**采用 C。** 测试体系与架构重构绑定推进：没有 domain 层就写不出不变量测试；没有端口注入就 fake 不掉。

关键取舍：
- **有状态 fake 而非 gomock**：要测"重复插入冲突""事务回滚""Outbox 失败"，gomock 表达不了状态。
- **SQLite 不再冒充 MySQL**：集成测试用 testcontainers 起真 MySQL，`//go:build integration` 隔离，nightly 跑。
- **覆盖率分层设阈值**：domain ≥90%、app ≥85%，不设整体数字。
- **golden + 契约双保险**：golden 守"行为没漂"，契约守"前后端没漂"。
- **门禁自检**：CI 必须能因"注入的失败"而红，否则 CI 无效。

## Consequences

### 变好的

- 测试从分钟级降到秒级（domain 纯单测）
- 规则组合可穷举（状态 × 角色），漏洞在写测试时就暴露
- 前后端类型漂移在编译期失败
- 并发缺陷由 `-race` + `t.Parallel` 常态化暴露

### 变差的

- 需要一次性写 testkit（约 800 行）与各模块 fake
- 集成测试需要 Docker（testcontainers），本地/CI 有环境要求
- golden file 会带来 PR diff 噪音（需人工 review）

### 需要跟进的

- CI 必须接入三档流水线与门禁自检
- flaky 测试 quarantine，不允许长期 retry
- mutation testing 先覆盖 domain 关键规则，逐步扩大

## 验证

```bash
# 1. 并行
( cd backend && go test -race -parallel 8 ./internal/... )

# 2. domain 无依赖且快
( cd backend && go test ./internal/*/domain/... )   # < 2s

# 3. 不变量矩阵
( cd backend && go test -run TestArticleVisibility -v ./internal/article/domain/ | grep -c PASS )  # ≥20

# 4. 门禁自检：注入 canary 失败测试，CI 必须红
```
