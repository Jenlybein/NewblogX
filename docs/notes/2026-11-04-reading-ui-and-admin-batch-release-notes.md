# 发布说明：阅读页互动与后台编辑批（2026-11-04）

本批对应 spec [#250](https://github.com/Jenlybein/NewblogX/issues/250)，落地票 #251–#258，决策依据是同一天的[决定清单](./2026-11-04-reading-ui-and-admin-batch-decisions.md)（43 条，逐条对应现象与根因）。

**顺序**：先后台（#255 / #256 / #257），再读者站（#251 / #253 / #254 / #258），后端计数账本（#252）与读者站并行。

## 一、用户可见的变化

### 读者站

1. **点赞后刷新，数字跟按钮一起更新**（#251）。硬刷新命中的是 30 秒匿名 SSR HTML，里面是点赞**之前**的计数；私有态请求本来就带着同一次的权威计数，过去只投影两个布尔把数字丢了。现在四个字段一起回填。匿名读者读到的计数仍可能最多脏 30 秒（这是缓存口径，不是 bug）。
2. **互动条重排 + 底部固定条退场**（#253）。顺序改为 点赞 / 收藏 / 评论 / 分享 / 底部；「底部」图标-only，点它滚到评论区起点。窄屏不再吸底，而是挂在 hero 下方（`hero` 形态），任何宽度只出现一份可见 —— 用户反馈的"底部多出一条同样的容器"随之消失。
3. **评论输入改成底部滑出面板**（#258）。评论区的内嵌输入框退役，换成「去发表评论」按钮；面板宽 `min(92vw, 640px)`、居中、无暗色遮罩，点面板外 / Esc / × 关闭，320ms 上滑（减少动态下直接出现）。「评论」按钮不再滚动 + 聚焦，改为直接开面板。
4. **删掉「评论第 X 页，每页 7 条」**（#253）。翻页按钮保留，只有第一页且没有下一页时整行都不渲染。
5. **顶栏「消息中心」改「消息」、「历史」套胶囊**（#254）。两者同档：≥1024px 常显，640–1023 收进头像菜单，<640 收进折叠面板。`/messages` 页面标题与术语仍是「消息中心」。
6. **正文列宽放开**（#256）。`--type-measure` 68ch → 80ch；≥1280px 时正文列上限 72rem 并居中，两侧不再空荡。

### 管理后台

7. **用户管理**（#255）。列表项样式修好、头像按三层回退（图 → 首字母 → 图标），新增封禁 / 解封（本人行禁用），编辑抽屉 420px。
8. **站点设置表单不再 100% 铺满**（#256）。按字段类型收到 180–560px，设置面板 760px 上限。
9. **合集 / 项目改卡片网格 + 居中编辑弹窗**（#257）。卡片 hover 才浮出编辑 / 删除，展示开关就地切换；弹窗信息卡 560px、「编排目录树」抽屉 480px 从右侧滑出且两容器成组居中，窄屏上下堆叠；新建后弹窗保持打开拿到 ID 再编排。独立的 `/articles/outline` 页面与菜单项**删除**，编排只存在于弹窗抽屉。

## 二、后端（#252）

- 30 分钟并账改为**按关系行重算覆盖**：`digg_count = COUNT(关系行)`、`favor_count = COUNT(收藏行)`，增量不参与持久化（软删的关系行不计入）。
- 视图 / 评论数保持 `列 += 增量`。
- 收藏内容列表（`favorite/contents`）补上增量合并，与详情 / 列表同口径。
- CDC 实时并账是**非目标**；决策与代价见 [ADR-0025](../adr/0025-count-ledger-and-reconciliation.md)。
- **无 DDL、无新表、无契约形状变化**（未改 DTO，`make openapi` 不需要重跑），Redis 键名不变。

## 三、部署注意

1. **读者站需要重新构建**：`frontend/.output` 里可能还留着旧的底部固定条产物。用户反馈的"底部多出一条"在本地无法复现（当时没有可用 dev server / 数据库），代码层已把第二个挂载点整体删除，但要看到效果必须重新 `pnpm build`（或 dev 重启），缓存产物不会自己更新。
2. 后台与读者站的 `tokens.css` 必须保持逐字节一致（`--type-measure: 80ch` 两侧同步改过），有门禁兜底。
3. 并账口径切换本身不需要数据迁移：第一次重算就把列值收敛到实际关系行数。

## 四、验证状态

- 读者站：`pnpm vitest run` 194 个文件 / 2224 条全绿；`lint` / `typecheck` 0 错误。
- 后台：`pnpm vitest run` 49 个文件 / 665 条全绿；`lint` / `typecheck` 0 错误；设计 token 与跨端 parity 门禁绿。
- 后端：`go build ./...`、`go vet ./...`、`go test ./...` 全绿；`archcheck` 两遍（含 `--skip-tests=false`）违反数 0。
- **MySQL 容器集成用例（已真跑，Docker 29.9.2 + `mysql:8.0` 容器）**：
  - `go test -tags integration -p 1 ./...` → **全绿（exit 0）**，15 个集成包全部 ok。
  - 并账契约用例 `TestReconcileArticleCount*` 8 条全过（其中 3 条打在真库上）。
  - **必须加 `-p 1`**：`log/writer` 与其它包并行跑时会撞同一个 ClickHouse 容器的端口/凭据，报 `Authentication failed` 假红；串行跑就绿。这是既有的测试基建约束，不是本批引入的。
  - **第一次真跑就抓到一个夹具缺陷**：`counter_flush_integration_test.go` 里"取消过的赞"那行写死 `user_id=300`，而 `seedUsers` 只建了 100 / 200 —— `article_digg_models.user_id` 有外键，直接 FK 失败。已补 `seedUser(t, db, 300)` 并加注释说明"同一用户对同一篇只能有一条点赞关系，所以取消过的那条必须换个用户"。这正是不跑真库就会一直绿着骗人的那类问题。
- **仍未能验证**：两个前端的界面观感（本机没有可用的 dev server / 数据库实例）——需要人工看一眼：互动条在 1280px 下只有一份、评论面板的滑出与关闭、合集卡片 hover、编辑弹窗与抽屉是否成组居中。

> 更正：本文件早前版本写过"本机 Docker 不可用，只做了 `go vet -tags integration`"。那是误判——依据是早期一次 `docker ps` 报权限不足与子代理的自述，未在后续复核。Docker 实际可用，上述用例均已真跑。

## 六、评审跟进（code-review，2026-11-04）

两轴评审（Standards / Spec）跑在 `main...HEAD` 上，**已修**：

1. ADR-0025 状态与索引不一致（正文写「已交付」、索引写「已接受」）→ 统一为**已接受**（MySQL 契约用例还没在容器里跑过，不配叫已交付）。
2. `--motion-slow` 曾在「零消费者」时被删过一次；评论面板上滑给了它第一个消费者 → 两端 `tokens.css` 重新加入 `320ms` / `0ms`（reduced-motion），面板改用 `var(--motion-slow)`，`motion-foundation` 门禁改成"有消费者才允许存在"。
3. 卡片 hover 层只降 `opacity` → 不可见按钮仍可点、仍进 Tab 序：改为 `visibility: hidden/visible` 参与过渡。
4. 抽屉从「`v-if` 挂载」改为**常驻挂载**：否则挂上即带展开态，宽度过渡永远不执行；窄屏同时补回 `display: none` 的收起态。
5. `CommentComposerSheet` 漏 import `ref` / `nextTick`（Nuxt 自动导入掩盖了它，单测直接红）→ 显式导入；顺带删掉已漂移的 `focusInput` 类型声明、无消费者的 `cancel` 事件与 `@cancel` 绑定、以及操作行的空 `<div />` 占位（改用 `justify-end`）。
6. 判据恒绿的 canary（`reader-private-state` 门禁里那条用本地拼的假字符串断言）→ 改成**从真实源码删掉两行计数**再喂给同一条判据。
7. 两条门禁的入口文件表仍指向 `collections.vue` / `projects.vue` → 指向真正承载裁剪编排的 `CollectionEditorOverlay.vue`。
8. 补齐三处缺测：后台头像兜底（表驱动）、评论面板的三条关闭途径（挂载后点击 / Esc）、弹窗抽屉展开态与独立保存入口。
9. 决策清单同步两处**文字与实现的偏离**：分享只放图标（站内没有分享计数，不造假数字）、底部按钮用 `IconArrowBarToDown`（`IconArrowDownToLine` 在本仓库的 tabler 版本里不存在）。
